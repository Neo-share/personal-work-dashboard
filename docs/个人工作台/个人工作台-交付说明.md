## 1. 产品概述

个人 AI 助手工作台是本地 Web 应用的首页（`/`），在同一页面管理 **待办**、**日程**、**定时任务**，并通过右侧 **个人助手** 用自然语言创建内容、生成 AI 初步结果、多轮修改与历史回溯。

**能力分层**：定时任务（调度）→ 物化待办（工作单元）→ 个人助手 AI（待办层）；定时任务 Tab **不直接调用大模型**。

## 2. 访问与运行

| 项 | 说明 |
|----|------|
| 前端 | http://localhost:5175（首页即个人工作台） |
| 后端 | http://localhost:3100 |
| 启动 | 仓库根目录 `pnpm install` → `pnpm dev` |
| 数据 | SQLite 持久化（`server/data/project-manager.db`） |
| AI 生成 | 配置 `server/.env` 中 `LLM_API_KEY`；未配置时自动降级为规则模板 |
| MCP（可选） | 配置 `FEISHU_MCP_HTTP_URL` 启用飞书文档上下文；见 §9 |

开发域（需求列表、仓库、扫描等）从工作台顶栏 **开发域** Tab 进入（`/dev-dashboard`）；开发域内顶栏 **个人工作台** 可返回首页。

## 8. Cursor Skill 与 Rules（可共享）

仓库内附带 **Cursor Agent 辅助配置**，随代码一并交付；接收方可直接在本仓库使用，或复制到其他项目。

### 8.1 项目 Skill（`.cursor/skills/`）

| Skill | 路径 | 触发场景 |
|-------|------|----------|
| **start-project** | `.cursor/skills/start-project/SKILL.md` | 「启动项目」「跑起来」「开 dev」——安装依赖、执行 `pnpm dev`、校验 `/health` |
| **workflow-driven-requirements** | `.cursor/skills/workflow-driven-requirements/SKILL.md` | 「按工作流」「S0-S5」「走控制层」——按 `agents/workflow.md` 状态机推进需求 |

**在 Cursor 中使用**

1. 用 Cursor 打开本仓库根目录（须含 `pnpm-workspace.yaml`）。
2. 对话中说触发语（见上表），或输入 `@start-project` / `@workflow-driven-requirements` 引用 Skill。
3. Agent 会按 Skill 内步骤执行；细则以 Skill 引用的 SSOT 文档为准（如 `agents/commands-checklist.md`），Skill 本身不重复全文。

**共享到其他项目**

| 方式 | 操作 |
|------|------|
| 整仓交付 | 直接 clone / 拷贝仓库，`.cursor/skills/` 随项目生效 |
| 仅复制 Skill | 将 `start-project/` 或 `workflow-driven-requirements/` 目录复制到目标仓库的 `.cursor/skills/` |
| 全局 Skill | 复制到用户目录 `~/.cursor/skills/<skill-name>/`，对所有 workspace 可用 |

> Skill 为 Markdown + YAML frontmatter（`name` / `description`）；不含密钥，可安全提交版本库。

### 8.2 项目 Rules（`.cursor/rules/`）

与 Skill 配套的硬性约束，Cursor 打开本仓库时自动加载：

| 规则文件 | 作用 |
|----------|------|
| `project-core.mdc` | Monorepo 包依赖方向、数据流、tRPC 约定 |
| `client.mdc` / `server.mdc` / `shared.mdc` | 各包写入边界与编码约束 |
| `agent-autonomy-s2-s4.mdc` | Agent 控制层 S3/S4 门禁与 scope 校验 |
| `worktree.mdc` | 多 worktree 并行开发时的路径写入权限 |

复制 `.cursor/rules/` 到目标仓库即可复用同一套 Agent 约束。

## 9. MCP 配置说明

本项目的 MCP 分两层：**应用运行时**（个人助手拉取飞书文档上下文）与 **Cursor IDE 开发侧**（可选，便于调试文档 MCP）。二者独立配置，互不依赖。

### 9.1 应用运行时：飞书 Document MCP（F4）

**作用**：用户在个人助手消息中粘贴飞书文档链接时，服务端经 HTTP 桥接拉取文档摘要，注入 `ContextRetriever.externalSnippets`，参与 AI 生成/修订上下文。

**与考题关系**：考题 RAG（E1–E3）为 **SQLite 内部检索**，不依赖 MCP；F4 为考题外增强，**未配置时不影响主链路**（自动降级为纯 DB 上下文 + 规则/LLM 模板）。

**配置步骤**

1. 复制环境变量模板：`cp server/.env.example server/.env`
2. 在 `server/.env` 中设置（示例见 `.env.example`）：

| 变量 | 必填 | 说明 |
|------|------|------|
| `FEISHU_MCP_HTTP_URL` | 是 | 本地 MCP HTTP 桥接地址，如 `http://127.0.0.1:3333/mcp/feishu/get_doc_content` |
| `FEISHU_MCP_TIMEOUT_MS` | 否 | 单次请求超时，默认 15000 |
| `FEISHU_MCP_MAX_DOCS` | 否 | 每条消息最多拉取文档数，默认 3 |
| `FEISHU_MCP_EXCERPT_CHARS` | 否 | 单文档摘要最大字符，默认 1500 |

3. 重启 `pnpm dev` 使配置生效。

**HTTP 桥接约定**（服务端 `feishu-doc-client.ts` 实现）

```http
POST {FEISHU_MCP_HTTP_URL}
Content-Type: application/json

{ "doc": "<飞书文档 URL 或 token>", "use_user_token": true }
```

响应 JSON 须含 `content` 或 `markdown` 字段（Markdown 正文）。飞书凭证与 OAuth 由桥接层自行管理，**勿写入本仓库或交付文档**。

**触发方式**：个人助手输入含飞书文档 URL 的消息（支持 `feishu.cn` / `feishu.net` / `larksuite.com` 的 wiki/docx/docs 链接）；无 URL 或未配置 MCP 时不发起外部请求。

**相关代码**：`server/src/assistant/mcp-context-retriever.ts` · `server/src/assistant/mcp/feishu-doc-client.ts`

**验收清单**（配置 `FEISHU_MCP_HTTP_URL` 后人工验收）：

| 项 | 状态 | 说明 |
|----|------|------|
| 消息含飞书文档 URL 时可拉取摘要并注入上下文 | 待验收 | 至少 3 个核心场景稳定 |
| 未配置或桥接失败时自动降级 | ✅ | 单测覆盖；主链路不受影响 |
| `pw.mcp.latency_ms` / `pw.mcp.fail` 指标 | ✅ | 记入 MetricsLedger |
| 新 MCP 经 ToolRegistry 注册，不改 chat 路由 | ✅ | 见 ARCHITECTURE.md §8 |

### 9.2 Cursor IDE：Feishu Document MCP（开发可选）

在 Cursor **Settings → MCP** 中启用 **Feishu Document MCP** 插件后，Agent 可在 IDE 对话内直接调用 `get_doc_content` 等工具（读设计稿、飞书需求文档等），**不经过**本应用 `3100` 端口。

| 场景 | 推荐配置 |
|------|----------|
| 验收个人工作台 AI 生成/修订 + 飞书文档上下文 | §9.1 运行时 HTTP 桥接 + `LLM_API_KEY` |
| 二次开发、读飞书 PRD/设计说明 | Cursor IDE MCP（与本应用 F4 可并存） |
| 仅演示考题基线（无外部文档） | 无需任何 MCP；内部 RAG + 可选 LLM 即可 |
