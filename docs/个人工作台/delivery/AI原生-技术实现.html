3. 档 T0：架构定界（人主导，AI 实现）

T0 · 人定架构

开发者凭经验先冻结不可由 AI 随意改动的边界，再交给 AI 写具体代码。本项目的 T0 决策如下：

决策项内容为何人定
能力三层定时任务（调度）→ 物化待办（工作单元）→ AI（待办层）防止 AI 在调度 Tab 直接调 LLM，成本与职责混乱
Monorepoclient / server / shared；依赖单向包边界错误会导致循环依赖与类型泄漏
数据流router(Zod) → service(SQL) → shared 类型分层一旦打破，后续 AI 补丁会越改越乱
助手五层护栏 → 意图 → Tool → 上下文 → 指标NL 入口必须有确定性安全层
AI 边界分流/护栏/CRUD 用规则；LLM 仅生成/修订 HTML无 Key 时主链路仍须可用
持久化SQLite，无完整 migration改 schema 策略须人工知晓

3.2 AI 在 T0 的角色

AI 不重新定义架构，而是读取 T0 约束后批量生成：

  • server/src/db/schema.ts 表结构
  • shared/src/types.ts 领域类型
  • server/src/trpc/router.ts procedure 骨架
  • client/src/components/personal-workbench/* 页面与组件
  • server/src/assistant/* 五层编排实现

4. 档 T1：需求 → 产品功能点（AI 生成 L4）

T1 · AI 分解产品

输入：个人工作台.md（考题需求原文）
输出：个人工作台-功能点.md（L1→L4 验收级功能点 + 实现状态）

粒度说明示例
L1 模块9 大模块页面框架、待办、日程、定时任务、助手、AI 结果…
L2 功能域模块内子域工具栏、卡片展示、AI 面板
L3 子功能可独立描述的行为四态筛选、逾期标记
L4 功能点验收级，可写测试02.05：已逾期筛选项仅展示带标签的进行中项

4.1 AI 生成规则

  • 每条 L4 必须可判定 ✅ / ⚠️ / ❌，禁止模糊表述
  • 标注能力分层约束（如 L1-04 定时任务不得直接调模型）
  • 与产品文档章节建立对照表，避免重复粘贴需求全文
  • 反向对照代码，产出「实现状态总览」

6. 档 T3：测试用例（AI 生成 + 人工审阅）

T3 · AI 验证

输入：L4 验收描述 + TL4 技术对照
输出：Vitest 单测 / 集成测 / 黄金话术回归（详见 测试用例文档）

前端组件RTL 交互AiResultPanel.test.tsx面板状态机

6.1 AI 生成用例的约束

  • 每条用例须能追溯到 L4 编号或 TL4 模块
  • 优先覆盖规则路径与降级路径（无 LLM_API_KEY）
  • LLM 相关用例 mock HTTP，禁止 CI 依赖外部 API
  • 集成测使用内存 SQLite（server/src/test/setup.ts）保证隔离

7. 档 T4：门禁交付（Agent 控制层）

T4 · 循环修复至通过

代码写入后执行 scope 校验与质量门禁；失败则 AI 认知修验，上限 15 轮。

步骤命令说明
Scope 自动检测pnpm agent:scope:auto识别改动域（server / client / shared）
Scope 校验pnpm agent:scope:<scope>禁止越界写入
日常门禁pnpm agent:gate:dev日常开发，exit 0 方可宣称完成
PR/CI 门禁pnpm agent:gate含 build + test:coverage
机械修复循环pnpm agent:s4:mechanical-loop优先自动修 lint / 类型错误

7.1 完成判定（DoD）

  1. pnpm agent:gate:dev 至少一次 exit 0
  2. 改动范围与 G.2 确认的路径一致
  3. L4 对应功能点状态已同步（若涉及验收项）
  4. 提 PR 前另跑 pnpm agent:gate

8. 无 AI 辅助 vs AI 辅助：工程侧对照

传统开发（无 AI 辅助）

  • 人读需求，手写功能清单与技术方案
  • 人逐文件编码，CRUD + 规则引擎手工实现
  • 人补测试，覆盖率靠自觉
  • 文档与代码易脱节

AI 原生开发（本项目实践）

  • 人只定 T0 架构边界；AI 生成 L4 / TL4 文档链
  • AI 按 TL4 批量写 service / 组件 / 助手五层
  • AI 按 L4 生成 Vitest 用例 + 黄金话术回归
  • Agent 控制层强制 scope + gate，文档编号可追溯

关键原则：AI 负责吞吐与一致性；人负责边界、安全与验收口径。二者分工通过 T0 冻结、T1–T3 文档链、T4 门禁串联。
