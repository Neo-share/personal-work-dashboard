1. 什么是 Skill

Skill 是存放在 .cursor/skills/ 下的 Markdown 指令包，带 YAML frontmatter（name / description）。Cursor Agent 在对话中识别触发语或 @ 引用后，会优先按 Skill 内步骤执行，而不是自由发挥。

与 Rules 的区别：Rules（.cursor/rules/*.mdc）是始终加载的硬性约束；Skill 是按需加载的操作手册，适合启动环境、走工作流、改特定模块等场景。二者配合：Rules 定底线，Skill 定步骤。
特性说明
格式Markdown + YAML frontmatter，可安全提交版本库
存放位置项目级 .cursor/skills/<name>/SKILL.md
扩展文件同目录下可有 reference.md、examples.md 等深读材料
不含密钥环境变量、API Key 等须在 server/.env 配置，Skill 只引用变量名

2. 如何调用 Skill

2.1 前置条件

  1. 用 Cursor 打开本仓库根目录（须含 pnpm-workspace.yaml）
  2. 使用 Agent 模式（会改代码/跑命令的对话）
  3. 确保 .cursor/skills/ 目录存在且未被忽略

2.2 三种调用方式

方式操作适用场景
自然语言触发对话中说 Skill 描述中的触发语（见下表）日常开发，Agent 自动匹配
@ 显式引用输入 @start-project、@project-manager-architecture 等明确指定步骤，避免误匹配
组合指令「按工作流实现 L1-05 黄金话术，加载架构 Skill」复杂任务，多 Skill 串联

2.3 调用示例

启动项目，跑起来本地 dev
@project-manager-architecture 新增待办列表筛选 API，只改 server 和 shared
按工作流 S0-S5 补齐 internal-knowledge-retriever 单测
@todo-knowledge-rag 调整 audit 类型的 RAG 召回策略

4. 各 Skill 详细说明

start-project启动本地开发环境

路径：.cursor/skills/start-project/SKILL.md

用途：在 monorepo 根目录安装依赖、并行启动 shared watch + server :3100 + client :5175，并验证 /health。

步骤命令 / 动作
1. 确认目录cwd 为含 pnpm-workspace.yaml 的根目录
2. 安装依赖pnpm install（首次或 lockfile 变更后）
3. 启动pnpm dev（Agent 终端建议后台运行）
4. 验证curl -s http://localhost:3100/health → {"ok":true}
5. 告知用户前端 http://localhost:5175 · 停止方式 Ctrl+C

前置要求：Node.js 18+ · pnpm 9.x

常见问题：端口占用 → 结束进程或改 PORT；改 schema 后 → 删 server/data/project-manager.db 重启；shared 类型报错 → pnpm --filter @project-manager/shared build

延伸阅读：agents/commands-checklist.md · agents/project-baseline.md

workflow-driven-requirements按 Agent 工作流执行需求

路径：.cursor/skills/workflow-driven-requirements/SKILL.md

用途：强制按 agents/workflow.md 的 S0–S5 状态机推进，避免 Agent 跳过范围确认或直接宣称完成。

S0 上下文确认
  → S1 需求结构化（Spec，复杂任务等人确认）
  → S2 任务计划 + G.2 改动范围确认
  → S3 在确认范围内实施
  → S4 scope 校验 + agent:gate:dev（PR 前另跑 agent:gate）
  → S5 交付报告（计划 vs 实际、验证结果、残余风险）
阶段人须确认Agent 产出
S1/S2是（默认）Spec、文件清单、验证命令
G.2不可豁免具体改动路径集合
S4—pnpm agent:scope:auto → pnpm agent:gate:dev exit 0

何时使用：端到端新功能、跨包改动、需要可追溯交付报告时；简单单文件修复可只说范围，但仍建议走 S4 门禁。

延伸阅读：agents/workflow.md · agents/commands-checklist.md

project-manager-architecture全栈技术架构模式

路径：.cursor/skills/project-manager-architecture/SKILL.md · 附 reference.md · examples.md

用途：新增页面/API/字段、排查包边界与数据流时，统一 monorepo 分层约定，防止 AI 越界写入或破坏依赖方向。

约束内容
包依赖shared ← server · shared ← client（禁止反向）
后端分层router(Zod) → service(SQL) → shared 类型，router 不写 SQL
前端数据流trpc.useQuery/useMutation → mutation 后 invalidate
双通道tRPC 结构化 CRUD · REST/SSE 长连接（如 /api/chat）
类型引用client 仅可 import server router 类型，不可引运行时代码

改动定位速查

新 tRPC 能力   → shared(类型?) → service → router → client hook + invalidate
实体字段       → shared → schema → service map → router Zod → client 展示
新页面         → pages/* + App.tsx Route + tRPC 消费
REST/SSE 协议  → routes/* + shared 事件类型 + client handler
纯 UI          → client 组件与 css

验证：改代码后 pnpm build；改 schema 删 DB；全栈任务跑 agent:scope:* + agent:gate:dev

延伸阅读：AGENTS.md · 各包 AGENTS.md · server/src/assistant/ARCHITECTURE.md

todo-knowledge-rag待办知识库 RAG 实现指南

路径：.cursor/skills/todo-knowledge-rag/SKILL.md · 附 reference.md · examples.md

用途：改待办 AI 生成/多轮修订、检索策略、snippet 溯源、RAG 验收前，对齐 Internal RAG 与 ContextRetriever 的边界。

体系入口消费者
Internal RAGretrieveForTodo(todoId, { intent })ai-result-service → LLM 生成/修订
ContextRetrievermcpContextRetriever.retrieve(...)personal-orchestrator 助手对话上下文

降级铁律：LLM 不可用或检索 0 条时，仍须完成待办流转（规则模板 / 关键词修订）。

任务决策树

新 resultType 检索策略  → internal-knowledge-retriever switch
调整召回规则/窗/上限    → internal-knowledge-retriever 常量与 SQL
改 LLM prompt/结构      → llm-ai-result-generator
改降级/异步调度         → ai-result-service
叠加飞书外部文档        → mcp-context-retriever + mergeExternalSnippetsIntoKnowledge
助手会话上下文（非 AI） → context-retriever / personal-orchestrator

明确不做：NL 意图 RAG、Soul 向量库、E4 embedding（规划中）、用 MCP 替代内部 RAG。

验证：pnpm --filter @project-manager/server test · 验收 K1–K5（见 RAG 方案文档）

延伸阅读：docs/个人工作台/待办知识库-RAG方案.md

5. Skill 与 Rules 配合

打开本仓库时，Cursor 自动加载 .cursor/rules/；Skill 在任务匹配时额外注入步骤。推荐组合如下：

任务类型推荐 Skill自动生效 Rules
首次 clone 后跑起来start-projectproject-core.mdc
跨包新功能workflow-driven-requirements + project-manager-architectureagent-autonomy-s2-s4.mdc · 包级 *.mdc
只改 server 助手project-manager-architectureserver.mdc · worktree.mdc
改待办 AI / RAGtodo-knowledge-ragserver.mdc
多 worktree 并行按域选 Skillworktree.mdc（禁止越界写入）

5.1 项目 Rules 索引

规则文件作用
project-core.mdcMonorepo 依赖方向、数据流、tRPC 约定
client.mdc / server.mdc / shared.mdc各包写入边界与编码约束
agent-autonomy-s2-s4.mdcS3/S4 门禁与 scope 校验
worktree.mdc多 worktree 路径写入权限

6. 场景选型矩阵

你说什么应加载的 SkillAgent 会做什么
「启动项目」start-projectpnpm install → pnpm dev → curl /health
「按工作流实现定时任务物化」workflow-driven-requirements + architectureS0–S5 推进，按 TL4 改 recurring-task-service

7. 共享与迁移

方式操作说明
整仓交付clone / 拷贝仓库.cursor/skills/ 与 .cursor/rules/ 随项目生效
仅复制 Skill复制 <skill-name>/ 目录到目标仓库 .cursor/skills/；需按需改路径引用
全局 Skill复制到 ~/.cursor/skills/<skill-name>/对所有 workspace 可用；start-project 含硬编码路径须改写
复制 Rules复制 .cursor/rules/非 monorepo 项目须删减包级规则

注意：project-manager-architecture 与 todo-knowledge-rag 强绑定本仓库目录与表结构；迁移到其他项目时需重写 reference 与示例路径。

8. 编写新 Skill（维护者）

  1. 在 .cursor/skills/<skill-name>/ 新建 SKILL.md
  2. YAML frontmatter 填写 name（与目录名一致）和 description（含触发语，Agent 靠此匹配）
  3. 正文写清：触发场景、前置条件、标准步骤、验证清单、常见问题、延伸阅读（链接到 SSOT 文档，勿重复粘贴全文）
  4. 复杂 Skill 可拆 reference.md（参数表）与 examples.md（任务示例）
  5. 在本 HTML 与 交付说明.html §8 同步索引
---
name: my-skill
description: 一句话说明 + 用户说什么时触发（中文触发语写进 description）
---

# 标题

## 触发场景
...

## 标准流程
1. ...
2. ...

## Agent 执行清单
- [ ] ...
